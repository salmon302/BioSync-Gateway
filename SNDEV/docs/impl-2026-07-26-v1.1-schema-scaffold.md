## 2. Specification Summary

The v1.0 schema (Alembic 0001–0006) covers core telemetry/lab/compliance tables only. The v1.1 advanced-analytics features (FR-3.11 PK/PD loop, FR-3.12 clinical chemistry, FR-3.13 digital-twin cohorts, FR-3.14 MRD/cfDNA sandbox, FR-3.15 LLM/RAG gateway, FR-3.16 scenario framework) have **no backing tables**, which blocks all downstream feature code.

This scaffold delivers the storage tier so the feature modules (`middleware/simulation/*`, `middleware/ai/*`, scenario orchestrator + API) can be built on top:
- 9 tables per SRS §6.1, all carrying append-only (or read-only-after-bulk-load) immutability per FR-3.8.1.
- A FK chain materializing the build-out order: `simulation_scenarios → scenario_runs → {synthetic_cohorts, chemistry_profiles, pkpd_worklists, cfdna_sandbox_runs, llm_runs, clinical_text_outputs}`, plus `pkpd_worklists → plates`, `chemistry_profiles/cfdna_sandbox_runs → simulations`, `clinical_text_outputs → llm_runs`.
- Reuse of existing `prevent_update()` / `prevent_delete()` trigger functions (from migration 0002); audit logging remains app-layer via `insert_audit_log` (consistent with v1.0).

## 3. Implementation Notes

### Files changed / created
- **Created** `middleware/alembic/versions/0007_v1_1_advanced_analytics.py`
  - `down_revision = '0006_complete_compliance_tables'`.
  - Creates 9 tables in FK-dependency order with `String(36)` uids, `JSONB` payload columns, `TIMESTAMPTZ` server-default timestamps, FKs, CHECK constraints (`scenario_runs.status`, `pkpd_worklists.origin`, `cfdna_sandbox_runs.detection_result`), and indexes on FK columns.
  - Attaches `prevent_update`/`prevent_delete` triggers to all 9 tables (defensive `CREATE OR REPLACE` of the two trigger functions included for self-containment).
  - `downgrade()` drops triggers then tables in reverse dependency order.
- **Modified** `middleware/models.py` — appended 9 ORM classes (`SimulationScenario`, `ScenarioRun`, `SyntheticCohort`, `ChemistryProfile`, `PkpdWorklist`, `CfdnaSandboxRun`, `LlmRun`, `ClinicalTextOutput`, `RagTemplate`) matching the migration columns and existing file style.
- **Created** `tests/unit/test_v1_1_schema.py` — DB-gated (skips without `DATABASE_URL`): asserts the 9 tables exist, both append-only triggers exist per table, and that INSERT-then-UPDATE/DELETE on a representative append-only table raises `IntegrityError`.
