## 3. Implementation Notes

### 3.1 G1 — Authenticity made explicit and guarded
**Files:** `database/seeds/illumina_udis_v1.0.0.json`, `tests/unit/test_barcode_authenticity.py`
- The manifest previously carried only a buried `provenance_note` admitting the sequences were synthetically generated (Illumina doc 1000000002694 returned 404). It is now explicit:
  - top-level `"authentic": false`,
  - `"source_document_status": "NOT RETRIEVED — … HTTP 404 …"`,
  - `"ingestion_procedure"` documenting the exact steps to ingest real sequences and flip `authentic` to true.
- Test additions:
  - `test_manifest_authenticity_is_explicit` — asserts the `authentic` boolean is declared and currently `False` (honest).
  - `test_authenticity_not_falsely_claimed` — **guardrail**: if `authentic` is `True`, requires a verified reference file (`illumina_udis_reference.json`) and exact set-membership match; otherwise skips. This prevents anyone from claiming real Illumina sequences without proof (NGS safety).
- **Verification:** `pytest tests/unit/test_barcode_authenticity.py` → 9 passed, 1 skipped (guardrail skipped because honestly non-authentic).

### 3.2 G4 — Well-click → FHIR Observation fetch (wiring)
**Files:** `frontend/src/utils/api.ts` (new), `frontend/src/pages/MicroplateEditor.tsx`
- New minimal authenticated API client (`utils/api.ts`): `getAuthToken()` (reads `localStorage['biosync_jwt']`), `apiFetch()`, and `fetchObservation(uid)`. Centralizes JWT/Bearer handling so future API calls share one path.
- `WellData` gained optional `observationUid?: string`.
- `handleWellClick` is now `async`: when a well has `observationUid`, it fetches `GET /api/fhir/Observation/{uid}` (endpoint already implemented in `middleware/api/routes/fhir.py`) and shows the result; falls back to any preloaded `well.observation` otherwise. Added `obsLoading`/`obsError` UI states in the observation overlay.
- **Verification:** `npx vitest run tests/microplate_editor.test.tsx` → 16 passed (no regression).

### 3.3 Structural blockers to FULL closure (documented, not fixed this session)
- **G1 full:** requires the official Illumina sequences (external doc currently 404). Code path + guardrail are ready; the data ingestion is a manual/external step.
- **G4 full (FR-3.2.3):** blocked by (a) no plate/well persistence — `middleware/api/routes/plates.py` endpoints are placeholders and there is no `Plate`/`PlateWell` SQLAlchemy model, so wells cannot carry an Observation link; (b) no frontend auth/token plumbing (login flow must store `biosync_jwt`). Both are larger workstreams outside Phase A quick-wins.
